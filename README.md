# ShareIt_practicum_Vasilkov

Сервис для шеринга вещей — учебный проект (Яндекс Практикум, курс Java-разработчик).

## Идея проекта

ShareIt позволяет пользователям делиться вещами: рассказывать, чем они готовы поделиться, находить нужную вещь и брать её в аренду на определённые даты. Владелец подтверждает бронирование, а после завершения аренды пользователь может оставить отзыв. Если нужной вещи нет в сервисе — можно оставить запрос на неё.

## Стек технологий

- Java 21
- Spring Boot 3.3.1 (Web, Validation, Data JPA)
- Hibernate / Spring Data JPA
- PostgreSQL
- Lombok
- Maven
- Docker Compose (локальный запуск БД)

## Архитектура

Классическая многослойная схема: **Controller → Service → Repository**, с разделением на модель (Entity), DTO и мапперы между ними. Пакеты организованы по фичам (feature-based), а не по типу класса:

```
ru.practicum.shareit
├── user       — пользователи
├── item       — вещи и отзывы (Comment)
├── booking    — бронирования
├── request    — запросы на вещи
└── exception  — обработка ошибок (@RestControllerAdvice)
```

## Функциональность

### Пользователи (`/users`)
- `POST /users` — создание пользователя
- `PATCH /users/{userId}` — редактирование
- `GET /users/{userId}` — просмотр
- `GET /users` — список всех пользователей
- `DELETE /users/{userId}` — удаление

### Вещи (`/items`)
- `POST /items` — добавление новой вещи
- `PATCH /items/{itemId}` — редактирование (только владельцем)
- `GET /items/{itemId}` — просмотр вещи (владельцу дополнительно видны даты бронирований)
- `GET /items` — список вещей владельца с датами последнего/ближайшего бронирования
- `GET /items/search?text=` — поиск доступных вещей по названию и описанию
- `POST /items/{itemId}/comment` — отзыв о вещи (только после завершённой аренды)

Все запросы к `/items` требуют заголовок `X-Sharer-User-Id`.

### Бронирования (`/bookings`)
- `POST /bookings` — создание запроса на бронирование
- `PATCH /bookings/{bookingId}?approved={true|false}` — подтверждение/отклонение владельцем
- `GET /bookings/{bookingId}` — просмотр бронирования (автором или владельцем вещи)
- `GET /bookings?state={state}` — список бронирований пользователя
- `GET /bookings/owner?state={state}` — список бронирований по вещам владельца

Поддерживаемые значения `state`: `ALL`, `CURRENT`, `PAST`, `FUTURE`, `WAITING`, `REJECTED`.

## Хранение данных

Схема БД описана в `src/main/resources/schema.sql` и выполняется автоматически при старте приложения (`CREATE TABLE IF NOT EXISTS`). Таблицы: `users`, `items`, `bookings`, `requests`, `comments`.

## Запуск проекта

1. Поднять локальную базу данных:
   ```
   docker compose up -d
   ```
2. Собрать и запустить приложение:
   ```
   mvn spring-boot:run
   ```
3. Приложение доступно на `http://localhost:8080`.

## Тестирование

Для проверки API подготовлены Postman-коллекции (спринт 14 — пользователи/вещи, спринт 15 — бронирования/отзывы). Импортируйте коллекцию в Postman и запустите её целиком через Collection Runner.

## Обработка ошибок

Единый обработчик исключений (`ErrorHandler`) возвращает понятные коды ответа:
- `400` — некорректные входные данные
- `403` — доступ запрещён (например, подтверждение чужого бронирования)
- `404` — сущность не найдена
- `409` — конфликт (например, email уже занят)
